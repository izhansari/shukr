"Restore from a copy" → `BackupListSheet`: the iCloud backups, newest first, counts from the name, "Fullest" marked; a tap downloads it if needed (≤ 60 s) and opens the restore sheet; "Choose a file…" for an Export.
- iCloud Backup (`ICloudCopy`, decisions icloud-copy-go A, icloud-backup-privacy A): the switch "Back up to iCloud"; once a day on opening (20 h gate; not on Low Power or expensive / constrained networks; backoff 1 h doubling to 24 h) the same .zip goes to the ubiquity container `iCloud.com.betternorms.shukr`'s hidden `Backups` folder (not in Files / iCloud.com; only shukr reads it), named "shukr backup yyyy-MM-dd HHmm (N prayers, N sessions, N photos).zip". Keeps the newest 3 + the fullest; prune deletes only backup-named files. Backups left in Documents by earlier builds move to Backups (`moveOutOfFiles`); iCloud's not-downloaded ".<name>.icloud" placeholders are read by their real name (`logicalName`). Emptier guard: a phone with under half the fullest backup's data (and ≥ 20 fewer) doesn't back up — "Backup paused", Restore From Your Backup / Back Up Anyway. Log: Application Support/YourData/icloud-copies.json.
- One state drives every indicator (`BackupState`: off · noICloud · none · backingUp · backedUp · stale · failed · emptier): the toolbar's symbol (orange on a problem), the row, `BackupCard` (top right) and the Settings tag.
- Trap: with the iCloud entitlement every ModelConfiguration needs `cloudKitDatabase: .none` (the store refused to open).
